# 项目资料设计草案

## 从两件日常工作出发

想查接口约定时，在「项目资料」搜关键词，直接读到仓库里的正文。收到客户访谈记录时，把文件拖进同一页面，保存到当前项目的 ForgeOS 资料库。

## 资料放在哪里

沿用项目已确认的双来源约定。以下界面与导入规则为首版提案。[项目知识双源管理](adr/ADR-004-project-knowledge-sources.md)

| 来源 | 适合保存 | 如何更新 |
| --- | --- | --- |
| Git 仓库 | 随代码交付的 README、接口约定、部署手册和正式 ADR | 保留原路径和格式，随 Git 提交更新 |
| ForgeOS | 项目背景、客户原始材料、访谈和环境备注 | 在项目内导入或编辑，保存为新修订 |

两类资料独立维护。项目可只使用其中一种，也可同时使用两种。仓库文档可以直接查看，拖入工作台的访谈记录只存入 ForgeOS。

## 浏览和引用

项目内提供一个资料入口。Git 按仓库目录浏览，ForgeOS 按分类浏览。搜索覆盖两处，结果显示来源和路径，可只看其中一处。

Markdown 默认预览，可切换到原文。其他仓库文本按原格式显示。

- **Git** 日常链接只带仓库相对路径 `path`。每次打开或刷新，读取登记仓库当前本地 HEAD 中的文件。旧版工作台链接即使带有 `commit`，也按路径打开当前版本。
- **ForgeOS** 日常链接只带资料标识 `key`，打开最新版。需要追溯时可在详情主动查看这份资料的旧修订。执行记录、知识审核等历史证据按其记录的提交或修订回读。

## 导入和修订

ForgeOS 新资料默认使用 Markdown，可粘贴正文，也可拖入多个 `.md` 或 `.txt`。文件默认取文件名作标题，粘贴默认取首个非空行，均可修改。`.txt` 作为纯文本导入 Markdown，保留换行和原有符号的字面含义。

提交前逐项预览。同一来源的相同正文自动跳过，同名且正文变化时可另存或明确选择更新已有资料。不同原件可保留各自出处，即使正文相同。

## 首版验收

- 搜同一关键词能找到两处资料，直接打开命中的正文。
- 导入一份 Markdown 和一份含 `#` 的 TXT，前者显示标题，后者保留字面符号。
- 更新一份 ForgeOS 资料后，原来的日常链接打开新版。详情里可回读旧修订，已有审核记录能核对当时的正文。
- 在登记仓库提交文档修改后，刷新同一路径可读到新正文，旧版带 `commit` 的工作台链接也打开新正文。
