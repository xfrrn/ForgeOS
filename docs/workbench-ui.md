# ForgeOS 工作台界面规范

本规范适用于 `web/` 下的工作台，包括登录、总览、列表、详情、表单和窄屏导航。设计沿用 `ecommerce-analytics-dashboard` 的暖色画布、白色卡片、顶部胶囊导航与紧凑的数据层级，使用 ForgeOS 的品牌、术语、路由与真实控制面数据。

## 设计变量

在[全局样式](../web/src/style.css)中维护 CSS 自定义属性。新增页面复用语义变量。确有新增视觉角色时，先在全局定义变量并在此处记录用途。

| 用途 | 变量与规则 |
|---|---|
| 页面与面板 | `--canvas` 用于暖白画布，`--surface` 用于白色卡片与浮层，`--surface-muted` 用于次级底面，`--surface-hover` 用于可交互区域悬停。 |
| 文本与链接 | `--ink` 用于标题和正文主信息，`--muted` 用于描述、时间和辅助信息，`--link` 用于可跳转的文本。 |
| 边框与焦点 | `--line` 用于白卡边框和区域分隔，`--control-line` 用于输入与描边按钮，`--focus` 用于可见的键盘焦点。 |
| 选中状态 | `--accent`、`--accent-ink`、`--accent-line` 分别用于鼠尾草绿选中态的底色、文字与边框。 |
| 业务状态 | `--positive`、`--warning`、`--danger`、`--info` 用于状态文字和图标，各自对应 `-bg`、`-line`。完成用绿，待处理或风险用琥珀，失败或破坏性操作用红，执行中等信息状态用蓝。状态始终带可读文字。 |
| 圆角 | `--radius-control` 为 8px，`--radius-panel` 为 16px。导航选中态和短状态标记使用胶囊圆角。 |
| 间距 | `--space-1` 至 `--space-6` 对应 4、8、12、16、20、24px。卡片间距以 16px 为基准，常规卡片内边距 20px，页面区段间距 24px。 |

主文本使用系统无衬线字体栈，保留中文字体回退。页面标题约 24–28px，卡片标题 16px，常规正文和控件文字 13–14px，时间与辅助信息 12px 左右。指标数值约 30px，使用等宽数字便于扫读。任务编号、SHA、命令与日志使用 `--font-mono`，正文和说明使用正文字体。面板以细边框建立层级，轻阴影用于菜单等浮层。

## 布局与导航

- 页面与顶栏共用居中的内容宽度，上限 1400px。外侧留白默认 32px，低于 1200px 用 24px，低于 700px 用 16px。
- 顶栏提供「项目」「Skill 库」「Agent 管理」「运行环境」、通知和账号菜单。项目首页在项目卡片上方显示 Worker 心跳、节点名额和控制面状态。项目内通过面包屑及「概览」「聊天」「Agent 管理」「任务」「审核与验收」「项目资料」导航，任务详情和待办链接包含所属项目。窄屏在第二行保留顶栏入口，退出登录从账号菜单进入。菜单支持键盘操作。
- 页面主标题每页一个。标题、必要描述与操作复用 `PageHeading`。宽屏操作靠右，空间不足时换行，保持主操作可达。描述补充范围、同步时间或当前约束。
- 项目概览复用 `MetricCard`，默认四列，低于 700px 时降为两列。首页项目卡片和项目概览的指标与对应项目队列使用相同范围。待办、当前执行与阻塞优先于仓库、检查、近期活动和状态分布。窄屏按阅读顺序堆叠。
- 项目任务列表按开发、代码审查、测试、调查、运维切换，默认打开开发。Git HEAD 和环境启动分别在系统检查入口查看。子任务沿用目标的工作类型并链接到目标。
- 列表、详情与表单沿用白色 `.panel`。详情从标题、状态、直接操作开始，然后按业务顺序展示区段。任务 ID、路径和标题可断行，日志、差异和宽表可在所属面板内滚动，页面保持单一纵向滚动。

## 组件与交互

| 场景 | 实现规则 |
|---|---|
| 标题、指标、占位与返回 | 复用[基础界面组件](../web/src/ui.tsx)中的 `PageHeading`、`MetricCard`、`EmptyState`、`BackLink`。卡片内有明确区段标题，操作文案直接说明下一步。 |
| 命令与跳转 | 使用 `.button` 及现有变体。提交、刷新、确认使用原生 `button`，页面跳转使用带 `href` 的链接。默认按钮描边，主要操作用炭色实底，危险操作使用对应状态变量。图标复用 `Icon`，图标按钮提供可访问名称。 |
| 状态与详情 | 复用[共享组件](../web/src/shared.tsx)的 `Status`、`Icon` 和 `Fact`。保留状态标签、关键信息和审核证据，细节区域布局由[详情样式](../web/src/detail.css)维护。 |
| 表格与筛选 | 按「区段标题和工具栏 → 表头和数据 → 分页」组织。使用语义表格与行分隔线，标识、状态和必要操作优先可见。筛选在窄屏换行。任务表在低于 640px 时收起 Worker 和时间列，原始信息可在详情查看。需要逐列比较的表格允许在面板内横向滚动。 |
| 加载、空结果、失败 | 初次读取提供可见的加载反馈，可用 `role="status"` 公布。空数据说明当前状态，筛选无匹配时提供调整或清除入口。失败显示具体问题，允许时提供重试。后台刷新保留已有内容，提交中防止重复操作。 |
| 表单与键盘 | 输入绑定可见标签，说明和字段错误与控件关联。保留 `:focus-visible`，当前导航使用 `aria-current`，展开按钮使用 `aria-expanded`。窄屏菜单关闭后保持可预测的焦点位置。文字、控件边界与焦点在底色上清晰可辨，业务状态由颜色和文字共同表达。 |
| 主题下拉框 | 讨论收件箱的工作类型选择复用主题下拉组件。选项面板沿用白色浮层、主题边框、鼠尾草绿选中态和勾选标记。方向键移动焦点，Enter 选择，Escape 收起。表单仍提交相应的工作类型值。 |
| 项目聊天 | 会话区展示 Owner 请求、Management 回复及所属项目的证据链接。操作卡展示待确认的目标、结果和任务链接。Agent 交接使用实际业务回执，窄屏将卡片和操作按阅读顺序排列。 |
| 项目接入 | 接入面板提供仓库链接克隆和已有本地仓库两种方式。克隆区域显示控制面机器上的托管目录、后台克隆进度以及接入成功后的路径和项目入口。 |

总览和列表使用控制面的真实返回值。`0` 表示有效计数，未知、读取中和失败分别按状态展示。新增图表需对应实际业务指标，并提供文字标签或可阅读的数据值。生产页面使用同源样式表，数据图形优先用原生元素属性和样式类表达。前端调整应保留深链接、权限判断、确认步骤、请求状态与证据入口。

## 开发与评审

1. 新建或修改页面前，对照总览、任务列表和任务详情中的同类结构，优先复用组件和变量。共享样式放入 `style.css`，详情专属布局放入 `detail.css`。
2. 提交前从仓库根目录运行 `npm --prefix web run build`。本地启动与代理配置见[本地运行指南](local-development.md#打开任务工作台)。
3. 在桌面与窄屏浏览器检查受影响的页面，例如 1440px 和 390px。核对导航与分组入口、焦点和键盘操作、表格或日志滚动、长中文标题、长路径与 SHA，以及加载、空结果、失败和有数据状态。
4. 对照现有业务流程验证关键交互。涉及共享组件或变量时，抽查总览、列表与详情三个页面，并说明未覆盖的环境或状态。变更共享视觉规则时同步更新本文。
